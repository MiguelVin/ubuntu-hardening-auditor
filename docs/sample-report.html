How to fix

ACC-001 · Only root has UID 0

Accounts with UID 0 besides root: toor
# Check whether these accounts are legitimate before changing anything
$ grep '^toor:' /etc/passwd
# If an account is not legitimate, lock and expire it
$ sudo usermod -L -e 1 toor

ACC-003 · sudo always asks for a password (no NOPASSWD)

NOPASSWD found at /etc/sudoers.d/deploy:1
$ sudo visudo -f /etc/sudoers.d/deploy  # remove NOPASSWD on line 1

NET-001 · UFW firewall is enabled and denies incoming traffic by default

UFW enabled=no, default incoming policy=DROP
$ sudo ufw default deny incoming
# If you use SSH, allow it BEFORE enabling or you will lose access
$ sudo ufw allow OpenSSH
$ sudo ufw enable

NET-002 · No risky service exposed on all network interfaces

Listening on all interfaces: 22/tcp SSH, 6379/tcp Redis
# Redis: bind it to 127.0.0.1 in its config, or block it:
$ sudo ufw deny 6379/tcp

NET-003 · IP forwarding is disabled

net.ipv4.ip_forward = 1
$ printf 'net.ipv4.ip_forward = 0\n' | sudo tee -a /etc/sysctl.d/60-hardening.conf
$ sudo sysctl --system

NET-004 · ICMP redirects are not accepted

all.accept_redirects = 0, default.accept_redirects = 1
$ printf 'net.ipv4.conf.all.accept_redirects = 0\nnet.ipv4.conf.default.accept_redirects = 0\n' | sudo tee -a /etc/sysctl.d/60-hardening.conf
$ sudo sysctl --system

LOG-001 · No SSH brute-force activity in auth.log

55 failed SSH logins; 2 IP(s) with 10+ attempts: 203.0.113.7 (40), 198.51.100.23 (15)
# Ban IPs automatically after repeated failures
$ sudo apt install fail2ban
# Turning off password login (SSH-002) makes guessing useless
$ sudo ufw deny from 203.0.113.7
$ sudo ufw deny from 198.51.100.23
